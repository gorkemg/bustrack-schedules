# Security maintenance

`Security checks` runs on pull requests, daily, and on demand, with read-only repository permissions. Its stable `security-check` job runs the unit tests and pip-audit 2.10.1 against the resolved direct and transitive requirements. An audit is a point-in-time check of known published vulnerabilities, not a code, secret, malware, or supply-chain integrity scan. Resolution is not a lockfile: transitive versions can change between runs. Dependabot groups daily pip and GitHub Actions security updates separately from routine minor and patch updates; review changes and CI before merging. Major version updates can still be proposed individually; the minor/patch filter only controls grouping. An `ignore` rule could also suppress security updates, so it is not configured. Repository settings must separately select `security-check` as a required branch check if desired.

The publication workflow audits the resolved requirements and runs tests before ETL, runs ETL with read-only repository permissions, and passes JSON files via a short-lived workflow artifact to the release job, which alone has `contents: write`. It retains the monthly schedule, manual runs, and main/beta rolling tags. A failed audit, test, or ETL prevents publishing. A per-ref concurrency group prevents overlapping runs for the same ref; GitHub may replace an older pending run when a newer run queues, so this is not a FIFO queue. Do not manually run the publication workflow for testing because it updates releases.

Both GTFS feeds are fetched over HTTPS with certificate verification, HTTPS-only redirects, connect/read timeouts, a 50 MiB archive cap, and a 10 MiB `routes.txt` cap. Only a single root `routes.txt` is read; other paths are never extracted. The PVTA HTTPS feed returned a ZIP and both feeds were successfully extracted on 2026-10-27. These limits can require adjustment when feeds grow. The read timeout is per socket read, not a total deadline; the workflow has a 30-minute job limit.

The HTML parsers still follow ordinary Requests redirects and accept unbounded HTML responses; extracted document links can include HTTP or external hosts. These links are published as metadata rather than downloaded by the parsers. Future work should validate page redirects, bound HTML bodies, and define a policy for published external links without silently dropping legitimate agency content.

## Dependency evidence

- Requests 2.32.3 was affected by [CVE-2024-47081](https://github.com/psf/requests/security/advisories/GHSA-9hjg-9r4m-mvj7), fixed in 2.32.4, and [CVE-2026-25645](https://github.com/psf/requests/security/advisories/GHSA-gc5v-m9x4-r6x2), fixed in 2.33.0. The latter concerns an extraction utility not used here. The selected 2.34.2 is an official [PyPI release](https://pypi.org/project/requests/2.34.2/).
- lxml 5.2.2 was flagged for [CVE-2026-41066](https://github.com/lxml/lxml/security/advisories/GHSA-vfmq-68hx-4jfw), fixed in 6.1.0. This affects particular XML parsers, not necessarily this project's HTML parsing. 6.1.3 is an official [PyPI release](https://pypi.org/project/lxml/6.1.3/).
- [pip-audit 2.10.1](https://pypi.org/project/pip-audit/2.10.1/) checks the resolved dependency tree against its advisory service. On 2026-10-27 the original requirements produced findings for Requests and lxml; the updated requirements produced no known vulnerabilities in a local Python 3.12 resolution. CI repeats the audit on Python 3.11.
- Action commit pins were checked against the corresponding upstream Git tag refs on 2026-10-27. Review future tag-to-commit changes and upstream release notes when Dependabot proposes them.
